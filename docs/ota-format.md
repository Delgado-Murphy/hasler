# OTA formats - the contract between the release builder and the box

*This page is for people who work on the release tools or the updater. It
describes, field by field, the files that travel from our build to a radio: the
release archive, its signed description, the signing keys and the channel
index. The build side (`scripts/release/`) and the radio side (`update/`) both
follow it, so a change here must be made on both sides at once. For the ideas
behind it, read [ota.md](ota.md) first; for what an owner sees, see
[Using your Hasler](using.md#updates).*

docs/ota.md is the why; this is the exact shape both sides build against.
Change it only together.

## Release tarball `hasler-<version>-arm64.tar.zst`

Built from an allowlist of repo paths, never a working tree. Reproducible:
sorted entries, uid/gid 0, mtime = SOURCE_DATE_EPOCH, no setuid, no devices,
symlinks only pointing inside the tree.

```
hasler-<version>/
  manifest.json            # copy of the signed manifest's payload (informational)
  files.sha256             # "<sha256>  <mode>  <relative path>" for every file below
  app/                     # haslerd package source + data (variants, catalog, stations, static)
  wheelhouse/              # every wheel for daemon[pi], aarch64 cp313, hash-locked
  requirements.lock        # pip --require-hashes lock used to build venv offline
  python/                  # bundled CPython (python-build-standalone), optional in v1
  bin/                     # pinned go-librespot, deno (sha256 recorded in files.sha256)
  integration/             # declarative system files, see below
  migrations/              # NNN_name.py, each with up(paths) and optional down(paths)
  selftest.py              # `python selftest.py --etc /etc/hasler` exit 0 = ok
```

`integration/` mirrors destinations under an allowlist only:
`systemd/*.service|*.timer` -> `/etc/systemd/system/`, `udev/*.rules` ->
`/etc/udev/rules.d/`, `sbin/hasler-*` -> `/usr/local/sbin/`, `bin/hasler-*` ->
`/usr/local/bin/`, `sudoers/haslerd` -> `/etc/sudoers.d/haslerd` (visudo -cf
first), `shutdown/hasler-*` -> `/usr/lib/systemd/system-shutdown/`,
`configtxt/hasler.block` -> the marked block in `/boot/firmware/config.txt`
(tryboot in v2; v1: only if unchanged or with explicit reboot flag).
Units reference `/opt/hasler/current/...`, never a version path.

## `release.json` (signed: `release.json.sig`)

```json
{
  "schema": 1,
  "product": "hasler",
  "version": "1.2.0",
  "seq": 12,
  "channel": "stable",
  "created": "2026-10-20T03:00:00Z",
  "expires": "2027-02-17T03:00:00Z",
  "kind": "patch|minor|major",
  "requires_migration": false,
  "min_from_seq": 9,
  "requires": {"os": "trixie", "moode": ">=10.0,<11", "python_abi": "cp313", "arch": "aarch64"},
  "config_schema": 1,
  "variants": ["hasler-hm", "excelsior"],
  "artifacts": [{"name": "hasler-1.2.0-arm64.tar.zst", "sha256": "...", "size": 12345678,
                 "url": "https://github.com/delgado-murphy/hasler-releases/releases/download/v1.2.0/hasler-1.2.0-arm64.tar.zst"}],
  "notes": "short changelog text",
  "keyring_seq": 1
}
```

## Signatures

OpenSSH signatures: `ssh-keygen -Y sign -f <key> -n hasler-release <file>`
produces `<file>.sig`. Verify on the box with
`ssh-keygen -Y verify -f <allowed_signers> -I <key id> -n hasler-release -s <file>.sig < <file>`.
`allowed_signers` is generated by the box from the verified keyring.

## Trust on the box `/etc/hasler/trust/` (root, 0444)

- `root.pub` - one or two root public keys (`root.pub`, `root2.pub`), installed once.
- `keyring.json` + `keyring.json.sig` (signed by a root key, namespace `hasler-keyring`):

```json
{"schema": 1, "keyring_seq": 1, "expires": "2027-10-20T00:00:00Z",
 "keys": [{"id": "release-2026a", "role": "release", "pub": "ssh-ed25519 AAAA...",
           "not_after": "2027-10-20T00:00:00Z"},
          {"id": "timestamp-2026a", "role": "timestamp", "pub": "ssh-ed25519 AAAA...",
           "not_after": "2027-10-20T00:00:00Z"}]}
```

A box accepts a new keyring only if a root key verifies it and its
`keyring_seq` is higher than the stored one.

## Channel index (signed by a timestamp key)

`https://delgado-murphy.github.io/hasler-releases/channels/<channel>.json` + `.sig`:

```json
{"schema": 1, "channel": "stable", "issued": "2026-10-20T03:00:00Z",
 "expires": "2026-11-03T03:00:00Z",
 "current": {"version": "1.2.0", "seq": 12,
             "release_url": "https://github.com/delgado-murphy/hasler-releases/releases/download/v1.2.0/release.json",
             "release_sha256": "..."},
 "halted": [11], "min_supported_seq": 9,
 "rings": {"0": ["<box-id>"], "1": [], "2": ["*"]}, "ring_open": {"0": "...", "1": "...", "2": "..."}}
```

## On the box

- `/opt/hasler/releases/<version>/` (root, read-only), `/opt/hasler/current`,
  `/opt/hasler/previous` symlinks.
- `/var/lib/hasler-update/` (user `hasler-update`): `incoming/`, `staged/<seq>/`.
- `/var/lib/hasler-apply/state.json` (root): `{"max_seq": 12, "keyring_seq": 1,
  "phase": "idle|trial|probation|committed|rolled_back", "from": "1.1.0",
  "to": "1.2.0", "boots": 0, "deadline": "...", "bad": [11],
  "history": [...]}` - every write: tmp + fsync + rename + fsync dir.
- `/etc/hasler/box.yaml` keys used by the updater: `channel` (bench|beta|stable),
  `update_mode` (auto|ask|off), `box_id` (random UUID), `checkin` (bool),
  `metered` (bool).

## Health endpoint (haslerd)

`GET http://127.0.0.1:8080/api/health` -> 200 with

```json
{"version": "1.2.0", "ok": true, "uptime_s": 42,
 "checks": {"mpd": true, "audio_card": true, "panel": "ok|absent|allowed_absent",
            "lamp": true, "web": true},
 "idle": true, "standby": true, "playing": false, "last_play_s": 1234}
```

`idle` = safe to update now (standby, nothing played for >= 10 min, no phone
casting). haslerd builds this in `haslerd/health.py` (`health_report(...)`).

## Amendments from the build (2026-10-20)

- `release.json` also carries `files_sha256` (the hash of the tarball's
  `files.sha256`) so root can verify a staged tree without re-extracting, and
  optionally `bundles_python` (false in v1: venvs use trixie's python3.13).
- The in-tarball `manifest.json` is `release.json` without `artifacts`;
  `files.sha256` lists every file except itself, mode in octal, symlinks
  listed but not hashed.
- Signature namespaces: `hasler-release` (release.json), `hasler-keyring`
  (keyring.json), `hasler-channel` (channel indexes).
- The keyring is served at `<base>/keyring.json(.sig)` next to `channels/`.
- `seq` = (major*10000 + minor*100 + patch)*100 + rc number, 99 for a final.
- `app/` holds `haslerd/` beside `config/{variants,catalog,stations,...}`, and
  `hasler_update/`; migrations ship inside `app/haslerd/migrations` (and as a
  top-level copy).
- `integration/` names starting with `hasler-update` are reserved for the
  updater itself and are installed only when a release commits.
- `selftest.py` gets `--state` as well as `--etc`.
- `state.json` also has `step`, `to_seq`, `baseline`, `integrated`,
  `migrated`, `reason`, `manual`, `failed`; the unprivileged side keeps
  `/var/lib/hasler-update/status.json`.
- Key-page buttons start `hasler-update-apply@<seq|rollback|rollback-X.Y.Z>.service`,
  allowed by a polkit rule (not sudoers: a `*` there also matches spaces).
